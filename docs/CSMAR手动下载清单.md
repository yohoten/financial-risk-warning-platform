# CSMAR 手动下载清单

> 适用场景：已登录 CSMAR（镜像站 `http://csmarayxdx.keyanwangshuju.com/`），可下载高权限表，但不能用脚本批量抓取。
>
> 目标：把 CSMAR 导出文件整理成项目 `data/raw/` 契约，跑通 `etl.run_pipeline`。
>
> 原则：**原始导出不改列名、不删列、不手工改单位**；列名翻译与单位换算由 `data/mapping/csmar.yaml` 和 `etl/mapping.py` 完成。

## 0. 下载前准备

### 0.1 建立目录

```text
data/incoming/csmar/raw/       # CSMAR 原始导出文件，原样存放
data/incoming/csmar/merged/    # 我后续合并后的中间文件（自动生成）
data/raw/                      # 项目 raw 契约（由映射层写入）
```

### 0.2 文件命名

统一使用：

```text
<表名>_<起始年>_<结束年>_<批次>.csv
```

示例：

```text
FS_Combas_2013_2025_A.csv
FS_Combas_2019_2025_B.csv
ST_events_2013_2026.csv
```

同一张表分多次下载时，保留批次后缀，不要覆盖。

### 0.3 下载日志

每下载一张表，在 `data/incoming/csmar/download_log.md` 追加一行：

| 表名 | 筛选条件 | 年份范围 | 行数 | 下载时间 | 备注 |
|---|---|---|---|---|---|
| 资产负债表 | 合并报表/年报/A股 | 2013–2025 |  |  | 分 A/B 两批 |

## 1. 所有表统一的筛选条件

| 设置项 | 选择 |
|---|---|
| 时间范围 | 会计期间 **2013-12-31 至 2025-12-31** |
| 报表类型 | **合并报表**（Typrep=A），不要母公司报表 |
| 报告类型 | **年报**，不要中报/季报 |
| 股票范围 | 沪深 **A 股**，剔除 B 股、H 股 |
| 行业范围 | 证监会行业代码 **C（制造业）**；界面不能筛就先下全 A 股 |
| 金额单位 | **元**（CSMAR 默认），不要勾“万元” |
| 导出格式 | CSV（UTF-8）优先，XLSX 也可 |
| 分批策略 | 单次行数超限按 2013–2018 / 2019–2025 拆分 |

> 年报的“会计期间”是 `12-31`；`01-01` 是年初数，不能当年报使用。

## 3. 分表操作说明

### ~~3.1 上市公司基本信息年度表~~

- **路径**：数据中心 → 单表查询 → 公司研究系列 → 上市公司基本信息 → 年度表
- **筛选**：年度 2013–2025；股票类型 A 股
- **字段**：证券代码、证券简称、行业代码、行业名称、上市日期、总股本
- **导出**：`basic_info.csv`
- **注意**：
  - 行业代码保留 `C13/C26/...` 原样，不要只留行业名称；
  - 总股本单位通常为股，映射层会换算为亿股。

### ~~3.2 资产负债表~~

- **路径**：数据中心 → 单表查询 → 公司研究系列 → 财务报表 → 资产负债表
- **筛选**：会计期间 2013-12-31 至 2025-12-31；报表类型 **合并报表**；报告类型 年报
- **字段**：至少包含资产总计、负债合计、所有者权益合计、流动资产合计、流动负债合计、存货、货币资金、应收账款、应付账款、固定资产净额、短期借款、长期借款
- **导出**：`FS_Combas.csv`
- **注意**：
  - 建议保留“报表类型”“公告日期”列，便于去重；
  - 同一公司-年可能因追溯调整出现多条，保留公告日期，按最新公告去重；
  - 金额单位是元，不要改。

### ~~3.3 利润表~~

- **路径**：财务报表 → 利润表
- **字段**：营业收入、营业成本、销售费用、管理费用、财务费用、利息费用、利润总额、净利润、研发费用
- **导出**：`FS_Comins.csv`
- **注意**：
  - 项目中的 `opex`（期间费用）= 销售费用 + 管理费用 + 财务费用，**三项都要下**；
  - 若利润表没有“利息费用”明细，先下“财务费用”，映射层会用财务费用代理；
  - “利润总额”作为 EBIT 的代理（息税前利润），论文口径需注明。

### ~~3.4 现金流量表~~

- **路径**：财务报表 → 现金流量表（直接法）
- **字段**：经营活动现金流量净额、投资活动现金流量净额、筹资活动现金流量净额、购建固定资产无形资产和其他长期资产支付的现金
- **导出**：`FS_Comscfd.csv`
- **补充**：折旧摊销在“现金流量表补充资料（间接法）”，若方便再下一份 `FS_Comscfi.csv`

### 3.5 ST 特别处理表

- **搜索关键词**：特别处理 / ST
- **字段**：证券代码、证券简称、实施日期、特别处理类型（ST/*ST）、撤销日期、公告日期
- **导出**：`ST_events.csv`
- **注意**：
  - 要**事件表**，不是某年的状态快照；
  - 标签按“首次实施日期所在年度”生成；
  - 2020 年退市新规前后 ST 口径有变化，保留原始类型字段。

> **当前替代方案（2026-11-11）**：CSMAR 能检索到《特殊处理变动文件》（股票市场系列 → 特殊处理与特别转让；
> 以及公司研究系列 → 经营困境/风险监测），但当前机构账号点进去显示“暂无数据”，没有下载权限。
> 已用 `scripts/build_st_labels_proxy.py` 从 `basic_info.csv` 的历年 `ShortName` 生成
> `data/incoming/csmar/ST_events_proxy.csv` 与 `data/raw/ST_events.csv` 代理事件表：
>
> - 代理事件 1,263 段、933 家公司、2001–2025；
> - `labels_st.csv` 覆盖 48,290 个 A 股公司-年（2013–2025），正样本 1,352（2.80%）；
> - 标签定义为“**年末证券简称以 ST/*ST 开头**”，不是交易所公告日；年内实施又撤销的样本会漏标；
> - 拿到官方表后，直接用官方 `ST_events.csv` 覆盖 `data/raw/ST_events.csv`，再跑
>   `python -m etl.csmar_import --step labels --write` 即可替换，无需改代码。

> **关于 `SPT_Company.csv`**：`CSMAR_download\pakage\公司文件222913114(仅供NU使用)\SPT_Company.csv`
> 是**公司主数据文件，不是 ST 事件表**。它只有 526 家公司、24 列（证券代码、简称、上市日期、行业、
> 当前状态 `Statco`、状态变动日 `Statdt` 等），没有 ST 实施日期、撤销日期、ST 类型，也不是年度面板。
> 可用来核对公司主数据或查看 2026 年当前 ST 简称（177 家带 ST/*ST），但不能生成完整 0/1 标签，
> 也不能替代官方《特别处理表》。

### 3.8 十大股东 + 董事会治理（股东已完成，董事会待补）

  - 导出：`TOP10_holders.csv`

  - 表名：`CG_Board`（董事会治理）或 `CG_Director`（董事长与总经理兼任）
  - 字段：证券代码、会计期间、董事会人数、独立董事人数、董事长是否兼任总经理（两职合一）、管理层持股比例
  - 筛选：2013-12-31 至 2025-12-31；A 股
  - 导出：`CG_board.csv`
  - 状态：☐ 待补；现有 `CG_manager.csv` 只有高管人数/持股/薪酬，没有 `duality`。

- **处罚**：公司研究系列 → 违规处罚
  - 字段：证券代码、处罚日期、处罚类型、处罚机构
  - 导出：`VIO_penalty.csv`
- 用途：按“公司-年”聚合为诉讼次数、处罚次数。

## 6. 导出后如何交接

1. 把文件放进 `data/raw/` 并按 §2 的导出文件名命名，**不要手工改列名、不要删列、不要改单位**；
2. 先下 P0 的 5 张表（当前已到 4 张，仅剩 ST 事件表）；
3. 执行导入与校验：

```bash
python -m scripts.convert_csmar_xlsx           # 仅现金流量表 XLSX 需要
python -m etl.csmar_import --step all --write  # 科目代码解码 + 三表合并 + 治理/审计映射
python -m scripts.validate_raw_data            # 报告：reports/data_quality/
```

4. 导入报告会打印每张表的行数、命中列、缺失字段与跳过行数，异常会写进 `docs/CSMAR数据可行性报告.md`；

> 说明：`etl.csmar_import` 负责"原始分表 → 契约表"；`etl.mapping` 负责"已合并表 → 契约表"，

## 8. 常见坑

1. **合并报表 vs 母公司报表**：必须选合并报表，否则资产负债率失真。
2. **会计期间 `01-01`**：那是年初数，不能当年报用。
3. **单位**：CSMAR 金额是元，项目口径是亿元；映射层会除以 `1e8`，不要手工改。
4. **同一公司-年多条记录**：追溯调整/更正公告会导致重复，保留公告日期，按最新去重。
5. **金融业**：若行业筛不掉，先下全 A 股，ETL 会剔除 J/K/S。
6. **CSMAR 导出上限**：单次可能限制 2–5 万行，按年份或交易所拆分。
7. **英文表头**：若导出是 `Stkcd/Accper/A001000000`，先不要改，交给我加表头翻译。
8. **B 股/H 股**：只保留 A 股，避免同一公司多地上市重复。
9. **ST 口径**：要事件表，不要年度状态快照；2020 年退市新规前后口径变化要保留原始类型。
10. **文本 PDF**：不要一次性下 3 万份，先按行业 × 年度 × ST 状态分层抽 800–1,000 个公司-年。
