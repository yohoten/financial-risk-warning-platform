## 一、数据层设计

### 1.1 样本企业选取策略

#### 1.1.1 行业范围

| 决策 | 建议 | 学术依据 |
|------|------|---------|
| 主样本 | 沪深A股制造业上市公司（证监会行业分类C类） | 制造业ST占比最高（约40%），样本量充足；Altman (1968) Z-score原始研究即聚焦制造业；国内主流文献（苗博威2020、李季鹏2024）均以制造业为主样本 |
| 扩展样本（稳健性检验） | 全行业A股（剔除金融、房地产） | 验证模型的行业泛化能力；金融业因会计准则差异需单独建模 |
| 排除行业 | 金融业（J）、房地产业（K）、综合类（S） | 金融企业资产负债结构特殊；房地产受政策周期影响过大；综合类业务异质性高 |

#### 1.1.2 时间跨度

| 参数 | 建议值 | 理由 |
|------|-------|------|
| 训练窗口 | 2015-2021年 | 按年扩展窗口交叉验证；覆盖供给侧改革→疫情→复苏 |
| 验证窗口 | 2022年 | 时间序列外验证（Out-of-Time, OOT），用于校准、阈值与模型比较 |
| 测试窗口 | 2023年 | 最终评估集，仅用于报告最终指标，不参与任何调优；结果只评估一次 |
| 锁箱窗口 | 2024年 | 待2026年官方ST标签披露后评估，不调参、不重选阈值 |
| 预测目标 | T+1年ST状态 | 使用T-1年及更早数据预测T年是否被ST，避免前视偏差（Look-ahead Bias） |

> **关键提醒**：严禁使用T年数据预测T年ST状态。ST判定基于T-1年年报，但年报在T年4月才披露，若用T年数据则存在信息泄露。建议使用T-2年财务数据预测T年ST状态，或在稳健性检验中讨论T-1 vs T-2的差异。

#### 1.1.3 ST/*ST与非ST配对方法

| 方法 | 建议 | 说明 |
|------|------|------|
| 主方案 | 1:3 近邻匹配 | 每个ST企业匹配3个同行业、同年度、总资产规模差异<30%的非ST企业。1:3在保证统计功效的同时控制样本不平衡度 |
| 备选方案 | 1:5 匹配 + 全样本对比 | 稳健性检验中使用1:5匹配和未匹配全样本分别建模，验证结论一致性 |
| 匹配变量 | 行业（证监会二级分类）、年份、总资产对数 | 控制行业效应和时间效应；资产规模是财务风险的最强混淆变量 |
| 匹配工具 | Python `sklearn.neighbors.NearestNeighbors` 或 `pymatch` | 自动化匹配，避免手动筛选的主观性 |

#### 1.1.4 样本量估算

```
制造业A股上市公司总数 ≈ 2,800家
2015-2022年间曾被ST的企业 ≈ 180-220家（含重复ST）
有效ST样本（剔除数据缺失>30%的）≈ 150-180家
1:3匹配后总样本量 ≈ 600-720家 × 8年 = 4,800-5,760条公司-年观测值
全样本（不匹配）≈ 2,800 × 8 = 22,400条公司-年观测值
```

> **建议**：主实验使用1:3匹配样本（约5,000条），稳健性检验使用全样本（约22,000条）。匹配样本用于模型开发和SHAP分析，全样本用于验证模型的泛化能力和阈值校准。

#### 1.1.5 剔除规则

| 剔除条件 | 理由 | 预计影响 |
|---------|------|---------|
| 上市不满3年 | IPO效应导致财务数据异常 | 剔除约15%样本 |
| 核心变量缺失>30% | 插补可靠性不足 | 剔除约8%样本 |

#### 1.3.2 特征筛选四步法

```
Step 1: IV值筛选（Information Value）
├── 计算每个特征的IV值
├── IV < 0.02 → 无预测力，剔除
├── 0.02 ≤ IV < 0.1 → 弱预测力，标记观察
├── IV ≥ 0.1 → 保留
└── 预期保留率：60-70%

Step 2: 相关性去冗余
├── 计算Pearson/Spearman相关系数矩阵
├── |r| > 0.85的特征对 → 保留IV较高者
├── VIF > 10的特征 → 逐步剔除VIF最高者
└── 预期保留率：80-90%（相对Step 1输出）

Step 3: PSI稳定性检验（Population Stability Index）
├── 将训练集按时间分为开发期和验证期
├── 计算每个特征在两期间的PSI
├── PSI > 0.25 → 不稳定，剔除
├── 0.1 < PSI ≤ 0.25 → 标记，后续监控
└── 预期保留率：85-95%

Step 4: Boruta重要性确认
├── 使用Boruta算法（Random Forest wrapper）
├── 迭代100次，p-value < 0.01确认为重要特征
├── Tentative特征结合业务判断决定去留
└── 最终保留特征数：35-50维
```

> **代码框架提示**：
> ```python
> # 特征筛选Pipeline伪代码
> from boruta import BorutaPy
> from sklearn.ensemble import RandomForestClassifier
> 
> # Step 1: IV值
> iv_scores = calculate_iv(X_train, y_train)  # 自定义函数
> X_step1 = X_train[iv_scores[iv_scores >= 0.02].index]
> 
> # Step 2: 相关性去冗余
> corr_matrix = X_step1.corr().abs()
> drop_cols = find_highly_correlated(corr_matrix, threshold=0.85, iv_scores=iv_scores)
> X_step2 = X_step1.drop(columns=drop_cols)
> 
> # Step 3: PSI
> psi_scores = calculate_psi(X_dev, X_val)  # 按时间分割
> X_step3 = X_step2[psi_scores[psi_scores <= 0.25].index]
> 
> # Step 4: Boruta
> rf = RandomForestClassifier(n_estimators=200, max_depth=8, n_jobs=-1)
> boruta = BorutaPy(rf, n_estimators='auto', verbose=0, max_iter=100)

> final_features = X_step3.columns[boruta.support_].tolist()
> ```

### 1.4 标签定义

#### 1.4.1 财务风险的操作性定义

| 标签方案 | 定义 | 优点 | 缺点 | 建议角色 |
|---------|------|------|------|---------|
| **方案A（主标签）** | T年被证监会实施ST或*ST处理 | 官方标准、无歧义、文献通用 | 样本极度不平衡（<5%）；滞后性强 | 主实验 |
| 方案B（辅助标签） | 连续2年净利润为负 | 提前预警信号；样本量更大 | 亏损≠ST，存在假阳性 | 稳健性检验 |
| 方案C（辅助标签） | Z-score < 1.81（Altman阈值） | 连续变量，可做回归 | 阈值争议大；不适用于中国情境 | 对照实验 |
| 方案D（增强标签） | A∪B∪C任一触发 | 扩大正样本量 | 标签噪声增加 | 敏感性分析 |

> **强烈建议**：主实验使用方案A（ST标记），这是学术界和实务界的共识标准。方案B/C/D仅用于稳健性检验和敏感性分析，证明模型在不同风险定义下的一致性。

#### 1.4.2 正负样本比例及处理

```
原始比例：ST样本约占3-5%（制造业2015-2022）
1:3匹配后：ST占25%，非ST占75%
全样本：ST占3-5%，非ST占95-97%

处理策略分层：
├── 采样层面：1:3近邻匹配（主实验）
├── 算法层面：scale_pos_weight = neg_count/pos_count（XGBoost内置）
├── 损失层面：Focal Loss（可选，自定义objective）
├── 阈值层面：最优阈值由Youden's J或F1-max确定，而非默认0.5
└── 评估层面：以AUC/F1/KS为主指标，Accuracy仅作辅助参考
```

        last_fetch_time = db.query("SELECT MAX(publish_time) FROM news_raw")
        new_articles = eastmoney_spider.fetch(since=last_fetch_time)
        deduplicated = dedup_by_title_similarity(new_articles, threshold=0.85)
        sentiments = finbert_batch_predict(deduplicated)
        db.insert(sentiments)
    
    def update_risk_signals(self):
        """风险信号：每周全量比对"""
        current_signals = qichacha_spider.fetch_all(target_companies)
        new_events = diff_with_db(current_signals)
        if new_events:
            alert_notification.send(new_events)
            db.insert(new_events)
```

### 2.2 XGBoost超参数调优策略

#### 2.2.1 Optuna搜索空间设计

```python
import optuna

def objective(trial):
    params = {
        # 树结构参数
        'max_depth': trial.suggest_int('max_depth', 3, 8),
        'min_child_weight': trial.suggest_float('min_child_weight', 1, 20, log=True),
        'subsample': trial.suggest_float('subsample', 0.6, 1.0),
        'colsample_bytree': trial.suggest_float('colsample_bytree', 0.5, 1.0),
        'gamma': trial.suggest_float('gamma', 0, 5),
        
        # 正则化参数
        'reg_alpha': trial.suggest_float('reg_alpha', 1e-3, 10, log=True),
        'reg_lambda': trial.suggest_float('reg_lambda', 1e-3, 10, log=True),
        
        # 学习率与树数量（联动设计）
        'learning_rate': trial.suggest_float('learning_rate', 0.01, 0.3, log=True),
        'n_estimators': trial.suggest_int('n_estimators', 100, 1000),
        
        # 类别不平衡处理
        'scale_pos_weight': trial.suggest_float('scale_pos_weight', 1, 10),
        
        # 固定参数
        'objective': 'binary:logistic',
        'eval_metric': 'auc',
        'use_label_encoder': False,
        'verbosity': 0,
        'n_jobs': -1,
    }
    
    # 早停机制：防止过拟合
    model = xgb.XGBClassifier(**params)
    model.fit(
        X_train, y_train,
        eval_set=[(X_val, y_val)],
        verbose=False,
        callbacks=[xgb.callback.EarlyStopping(
            rounds=50, 
            metric_name='auc',

    y_pred_proba = model.predict_proba(X_val)[:, 1]
    auc = roc_auc_score(y_val, y_pred_proba)

# 贝叶斯优化 + 剪枝
study = optuna.create_study(
    direction='maximize',
    sampler=optuna.samplers.TPESampler(seed=42),
    pruner=optuna.pruners.MedianPruner(n_warmup_steps=20)
)
study.optimize(objective, n_trials=100, show_progress_bar=True)
```

#### 2.2.2 调优策略要点

| 策略 | 说明 | 理由 |
|------|------|------|
| 贝叶斯优化（TPE） | 替代网格搜索/随机搜索 | 在高维空间中效率提升5-10倍（Bergstra et al., 2011） |
| 早停回调 | `EarlyStopping(rounds=50)` | 防止过拟合；自动确定最优树数量 |
| Median Pruner | 提前终止无望的trial | 节省30-50%计算时间 |
| learning_rate × n_estimators联动 | 低学习率配高树数，反之亦然 | 两者强耦合，独立搜索效率低 |
| scale_pos_weight纳入搜索 | 而非固定为neg/pos比 | 最优权重不一定等于样本比的精确倒数 |
| 多指标监控 | 主优化AUC，同时记录F1/KS/Brier | 避免单一指标过优化 |

### 2.3 类别不平衡处理方案

#### 2.3.1 多层处理策略

```
Layer 1: 采样层
├── 主方案：1:3近邻匹配（数据层面平衡）
├── 备选：SMOTE（仅在匹配后仍不平衡时使用）
└── 注意：SMOTE仅在训练集上应用，验证集/测试集保持原始分布

Layer 2: 算法层
├── XGBoost内置：scale_pos_weight（由Optuna搜索最优值）
├── class_weight='balanced'（sklearn模型使用）
└── 自定义Focal Loss（可选增强）

Layer 3: 阈值层
├── 默认0.5不适用于不平衡场景
├── Youden's J统计量确定最优阈值：J = Sensitivity + Specificity - 1
├── F1-max阈值作为备选
└── 业务导向阈值：根据误报成本调整（如银行风控偏好低误报）

Layer 4: 评估层
├── 不使用Accuracy作为主指标
├── 主指标：AUC + KS + F1
├── 辅助指标：Brier Score + 校准曲线
└── 分群评估：按行业/规模/年份分组检查性能一致性
```

### 2.4 模型评估体系

#### 2.4.1 评估指标详解

| 指标 | 公式/含义 | 合格线 | 优秀线 | 为什么重要 |
|------|----------|-------|-------|-----------|
| **AUC-ROC** | ROC曲线下面积 | ≥0.85 | ≥0.90 | 阈值无关的综合判别力；文献对标基准 |
| **KS统计量** | max(TPR - FPR) | ≥0.40 | ≥0.50 | 金融风控行业标准；直观反映最大区分度 |
| **F1-Score** | 2×P×R/(P+R) | ≥0.60 | ≥0.75 | 兼顾精确率和召回率；不平衡场景下比Accuracy可靠 |
| **Brier Score** | mean((p-y)²) | ≤0.15 | ≤0.10 | 概率校准质量；低Brier意味着预测概率可信 |
| **校准曲线** | 预测概率vs实际频率的偏离度 | ECE<0.05 | ECE<0.02 | 预警概率的业务可解释性基础 |

### 2.6 模型迭代与监控

#### 2.6.1 PSI漂移检测

```python
def calculate_psi(expected, actual, buckets=10):
    """
    Population Stability Index
    PSI < 0.1: 稳定
    0.1 ≤ PSI < 0.25: 轻微漂移，需关注
    PSI ≥ 0.25: 显著漂移，需重训练
    """
    eps = 1e-4
    breakpoints = np.quantile(expected, np.linspace(0, 1, buckets + 1))
    expected_pct = np.histogram(expected, bins=breakpoints)[0] / len(expected)
    actual_pct = np.histogram(actual, bins=breakpoints)[0] / len(actual)
    psi = np.sum((actual_pct - expected_pct) * np.log((actual_pct + eps) / (expected_pct + eps)))
    return psi

# 监控频率：每月计算一次PSI
# 触发条件：任一核心特征PSI > 0.25 或 模型AUC下降 > 0.03
# 响应动作：标记告警 → 人工审核 → 决定是否重训练
```

| 触发条件 | 动作 | 频率 |
|---------|------|------|
| 日历触发 | 每季度末自动重训练 | 季度 |
| PSI触发 | 核心特征PSI > 0.25 | 事件驱动 |
| 性能触发 | OOT AUC下降 > 0.03 | 事件驱动 |
| 数据触发 | 新增ST样本 > 20家 | 事件驱动 |

    # 7. 免责声明与方法论说明
    
    doc.build(elements)
    return f"reports/{stock_code}_risk_report.pdf"
```

### B.2 与原始方案的差异说明（答辩可主动交代）

| 项 | 原方案 | 实际实现 | 原因 |

## 附录C：答辩常见问题预判与应答策略

| 可能提问 | 应答要点 |
|---------|---------|
| "为什么选XGBoost而不是深度学习？" | ① 表格数据上集成学习通常优于深度学习（Grinsztajn et al., 2022）；② SHAP原生支持，可解释性强；③ 样本量~5000不足以支撑深度学习；④ 文献对标充分 |
| "SHAP值和传统特征重要性有什么区别？" | SHAP基于博弈论Shapley值，满足局部准确性、一致性和缺失性三大公理；传统Feature Importance仅反映全局平均贡献，无法解释单样本 |
| "你的模型能真正用于实务吗？" | ① 定位为研究工具和辅助决策支持，非自动化交易系统；② SHAP可解释性使结果可审计；③ PSI监控确保模型稳定性；④ 需结合专家判断使用 |
