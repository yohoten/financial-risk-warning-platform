## 一、环境准备

### 1.1 本地运行

| 步骤 | 命令 | 校验 |
|------|------|------|
| 创建环境 | `python -m venv .venv` | `python -V` ≥ 3.10 |
| 激活（Win） | `.venv\Scripts\activate` | 提示符出现 `(.venv)` |
| 激活（mac/Linux） | `source .venv/bin/activate` | 同上 |
| 安装依赖 | `pip install -r requirements.txt` | `pip list \| findstr xgboost` |
| 自检 | `python -m pytest -q` | `35 passed` |

> 若 `pyarrow` 因 numpy 版本报错：系统会自动降级为 CSV 存储，不影响任何功能
> （见 `etl/io_utils.write_table`）。如需彻底解决：`pip install pyarrow==14.0.2`。

### 1.2 Docker 运行

```bash
docker compose up -d --build         # 首次构建约 3-6 分钟
docker compose logs -f               # 观察启动日志（会打印训练进度）
curl http://localhost:8501/_stcore/health   # 期望返回 ok
```

### 1.3 环境变量

复制 `.env.example` → `.env`（`.env` 已被 gitignore）。仅在使用真实数据采集时需要：

| 变量 | 用途 | 缺失影响 |
|------|------|---------|
| `CSMAR_USER/PASSWORD` | CSMAR 导出（手动导出时不需要） | 无法自动拉取财务数据 |
| `QICHACHA_KEY` | 司法风险 API | 司法特征为 0，模型照常运行 |
| `DEMO_MODE` | 1=演示数据 | 0 时读取 `data/raw` 真实数据 |
| `LOG_LEVEL` | 日志级别 | 默认 INFO |

## 二、首次初始化（三条命令）

```bash
python -m etl.run_pipeline      # 数据 + 特征 + 筛选（缺原始数据会自动生成演示数据）
python -m models.train --trials 30
python -m models.evaluate && python -m models.shap_analysis && python -m models.monitor
```

**预期产物与耗时（演示规模 240 家公司 × 10 年）**：

| 产物 | 路径 | 耗时 |
|------|------|------|
| 特征面板 | `data/feature_store/panel_features.parquet` | 4 s |
| 建模输入 | `data/feature_store/panel_model_input.parquet` | 同上 |
| 特征清单 | `data/feature_store/selected_features.json` | 同上 |
| 模型权重 | `models/artifacts/xgboost_final.json` | 30-60 s（含 CV） |
| 指标 | `models/artifacts/metrics.json` | 同上 |
| 评估报告 | `models/artifacts/evaluation_report.md` | 5 s |
| SHAP 缓存 | `cache/shap_values.pkl` | 3 s |
| 监控报告 | `models/artifacts/monitor_report.json` | 2 s |

## 三、五大模块操作指引

### 3.1 首页（app.py）

- **状态自检区**：5 个绿点分别对应特征面板、模型权重、SHAP 缓存、评分缓存、评估报告。
  任一项为 ⚪ 时，页面会提示对应命令。
- **指标卡**：样本规模、特征维度、验证 AUC、KS —— 用于开场 30 秒说明"系统是什么水平"。

### 3.2 📊 数据看板

| 操作 | 结果 | 讲解要点 |
|------|------|---------|
| 查看"行业态势" | 行业平均风险 + 气泡（气泡=高风险企业数）+ 行业×年度热力图 | 说明存在行业性风险周期 |
| 查看"时间趋势" | ST 家数（柱）+ ST 占比（线）+ 预测均值（点线） | 强调"预测领先于事实"的预警价值 |
| 调整"展示企业数" | TOP-N 排行联动 | 展示交互性 |
| 查看"宏观环境" | 当年 vs 近五年均值雷达 | 说明宏观作为控制变量的作用 |
| 查看"数据质量" | 缺失率、重复、正样本率 | 展示数据治理意识 |

### 3.3 🏢 企业诊断

1. 下拉选择企业（默认风险最高者）与年度；
2. 读取四张卡：风险等级、ST 概率、风险分位、同业排名；
3. 左侧雷达：六维健康度（相对同侪分位，60 分为同业基准线）；
4. 右侧瀑布图：红色向右=推高风险，绿色向左=降低风险；顶部标题含 P(ST)；
5. 底部：历史轨迹 + 归因明细 + 核心指标同业对标。

**演示话术示例**："这家企业 ST 概率 68%，主要来自资产负债率偏高（+0.42 log-odds）与
经营现金流对净利润覆盖不足（+0.31），而毛利率高于同业（−0.18）起到缓冲作用。"

### 3.4 📋 批量预警

| 输入方式 | 说明 |
|---------|------|
| 粘贴代码 | 逗号/空格/换行分隔，自动去重与补零 |
| 上传 CSV | 需含 `stock_code` 或 `股票代码` 列 |
| 全市场按钮 | 一键对当期全部企业评分 |

阈值滑块会**实时重算风险等级**（不改动模型概率），导出 Excel 含"汇总"Sheet。

### 3.5 🔍 模型解释

| Tab | 交互 | 结论点 |
|-----|------|--------|
| 全局重要性 | 滑块调 TOP-N | 偿债/现金流维度贡献最高，与文献一致 |
| 依赖效应 | 下拉选特征 | 资产负债率在 0.6-0.7 区间 SHAP 陡增，可作业务阈值 |
| 交互效应 | 滑块调参与特征数 | 说明"高杠杆 + 弱现金流"的协同恶化 |
| 模型对比 | 表格 + 柱状图 | XGBoost 相对 LR 的提升幅度 |
| 漂移监控 | PSI 条形图 + 处置建议 | 说明模型需要定期重训练的工程闭环 |

### 3.6 📄 报告导出

| 产出 | 步骤 | 注意 |
|------|------|------|
| 单企业 PDF | 选企业+年度 → 生成 PDF → 下载 | 中文字体内置，2-3 页；同时归档到 `reports/` |
| 批量 Excel | 选年度+阈值 → 下载 | 含明细 + 汇总两个 Sheet |
| 评估报告 | 直接下载 Markdown | 由 `models.evaluate` 生成 |
| 数据字典 | 直接下载 CSV | 与 `config/feature_registry.py` 同源 |

## 四、日常运维

### 4.1 数据更新 SOP（季度）

```bash
# 1. 覆盖 data/raw 下的原始表（保持字段与主键不变）
# 2. 重跑流水线与模型
python -m etl.run_pipeline
python -m models.train --trials 30
python -m models.evaluate && python -m models.shap_analysis

# 3. 漂移与性能复核
python -m models.monitor --reference 2022 --current 2024

# 4. 刷新前端评分缓存（也可由页面首次访问自动触发）
python -c "from models.predict import refresh_predictions; refresh_predictions()"
```

### 4.2 重训练触发判据

| 条件 | 判据 | 动作 |
|------|------|------|
| 日历 | 每季度末 | 常规重训练 |
| 特征漂移 | 任一核心特征 PSI > 0.25 | 立即重训练 |
| 性能衰减 | OOT AUC 下降 > 0.03 | 人工复核后重训练 |
| 数据触发 | 新增 ST 样本 > 20 家 | 重训练 |
| 手动 | 评审/导师要求 | 按需 |

### 4.3 备份与迁移

```bash
# 需要备份的只有"不可再生"的部分
data/raw/                 # 原始数据（可再生则不必）
models/artifacts/         # 模型与报告（能重训则不必）
# 全量迁移推荐直接打包镜像
docker save risk-warning-platform:1.0 -o risk_platform_v1.0.tar
```

### 4.4 产物清单与清理

| 目录 | 是否可删 | 恢复方式 |
|------|---------|---------|
| `data/cleaned/`、`data/feature_store/` | 可删 | `python -m etl.run_pipeline` |
| `models/artifacts/` | 可删 | `python -m models.train` + `evaluate` |
| `cache/` | 可删 | 首次访问自动重建 |
| `reports/` | 可删 | 重新导出 |
| `data/raw/` | **不可删** | 需重新导出/采集 |

`make clean` 会清理除 `data/raw` 外的全部产物。

## 五、故障排查

| 症状 | 原因 | 处理 |
|------|------|------|
| 页面红框"未找到特征数据" | 未跑流水线 | `python -m etl.run_pipeline` |
| 页面提示"未找到模型" | 未训练 | `python -m models.train` |
| "SHAP 归因不可用" | 无 `cache/shap_values.pkl` | `python -m models.shap_analysis` |
| 图表中文变方块 | 使用 matplotlib 的场景 | 设置 `font.sans-serif`（平台图表已用 Plotly 规避） |
| `ImportError: pyarrow requires NumPy 2.0` | pyarrow 版本过新 | 自动降级 CSV；或 `pip install pyarrow==14.0.2` |
| 训练报"训练集为空" | 数据年份不足 2015-2023 | 检查 `settings.PANEL_YEARS` 与数据年份 |
| 控制台中文乱码 | Windows GBK 终端 | 已强制 UTF-8；必要时 `chcp 65001` |
| Docker 启动后一直 unhealthy | 首次启动在训练 | 等待 2-3 分钟；`docker compose logs -f` 观察 |
| Excel 导出失败 | 缺 openpyxl | 自动降级 CSV；或 `pip install openpyxl` |
| 批量预警"代码未找到" | 代码不在当期样本 / 未补零 | 换年度；确认 6 位代码 |

## 七、维护约定

1. **改特征**：`config/feature_registry.py` 加定义 → `etl/feature_engineering.py` 加计算 →
   `python -m scripts.gen_data_dictionary` 同步文档 → 重跑流水线与测试。
2. **改阈值**：只改 `config/settings.py`，禁止在页面或模型里硬编码。
3. **改接口**：`models/predict.py` 的返回列只增不改，避免前端散弹式修改。
4. **提交前**：`python -m pytest -q` 必须全绿；涉及架构变更时同步更新
   [系统架构设计说明书](./系统架构设计说明书.md)。
