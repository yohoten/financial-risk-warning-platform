# ADR-001 · 展示层一次性迁移为 Vue 3

> | 元信息 | 值 |
> |---|---|
> | 状态 | ✅ 已采纳并已实现 |
> | 日期 | 2026-11-15（设计）/ 2026-11-17（落地） |
> | 关联文档 | 《大屏平台开发设计方案》 |
> | 影响面 | `web/`、`streamlit_app/`、`api/` |

## 1. 背景

项目早期展示层为 Streamlit（7 页），而平台真实定位是**大屏/看板**。Streamlit 在深色大屏视觉、精细布局、分辨率自适应、多屏联动、动效交互上能力有限。同期旧项目 `risk-warning-platform` 已有成熟的 Vue 3 + ECharts 看板骨架。

## 2. 候选选项

| 选项 | 说明 | 结论 |
|---|---|---|
| A. 双前端并存 | Streamlit 与 Vue 并行维护 | ❌ 双倍维护成本，且两套口径易漂移 |
| B. 渐进式迁移 | 先 Vue 后逐页替换 Streamlit | ❌ 迁移期双轨并存，风险与 A 相同 |
| C. 一次性 Vue 化 | Vue 为主交付，Streamlit 降级为离线演示 | ✅ **采纳** |

## 3. 决策

**采用 C**：以 Vue 3 SPA 为唯一对外主前端，Streamlit 保留为内网离线演示与快速原型的**辅助形态**，两者共用同一领域层 `models/`。

## 4. 关键配套决策

- **服务边界**：所有取数经 FastAPI（`api/`），前端不得直读 `cache/` 与 `models/artifacts/`；
- **口径单一来源**：风险等级、阈值、色板、特征口径统一由 `config/feature_registry.py` 与 `web/src/lib/theme.ts` 提供；
- **不引入重型组件库**：沿用 ECharts + 原生 CSS，避免构建体积与学习成本膨胀；
- **迁移标注**：文档中区分 `[复用]`（旧项目直接迁移）、`[移植]`（逻辑整体搬迁 + 适配新契约）、`[新建]`（原创实现）。

## 5. 后果

**正面**：展示层能力上限提升；前后端职责清晰；旧项目资产可系统性复用。

**负面**：失去 Streamlit 的「零前端依赖」快速迭代能力；`streamlit_app/` 需要额外维护以支持离线演示。

**现状核对**：Vue SPA 实际 **12 个视图**（README 原写「九视图」，已在本轮文档治理中校正）。
