## 2. 问题清单（11 项，含证据与影响分析）

### P-01｜预处理阶段的三处前视泄漏（与论文表述冲突）· P0

**证据**

| 位置 | 现状 | 泄漏性质 |
|---|---|---|
| `etl/clean_financial.py:60` | `.interpolate(method="linear", limit=max_gap, limit_direction="both")` | `both` 允许**用未来年份**回填缺失值（如 2020 缺口由 2021 补） |
| `etl/clean_financial.py:66-71` | 行业-年度中位数、全局中位数在**全面板**上计算 | 2023 测试年的分布参与统计量估计 |
| `etl/clean_financial.py:87` | `out[col].quantile(lower/upper)` 在**全面板**上估计缩尾分位点 | 2023 测试年的极端值影响裁剪边界 |

**论文表述**（`docs/Attachment/论文_第1-4章.md:189`）：

> 「对连续特征按**训练窗口**估计的 1% 与 99% 分位点进行缩尾，**避免测试集信息泄露**」

**影响**

1. **学术风险（最高）**：论文明确声称的防泄漏措施在代码中不存在。答辩若被追问「缩尾分位点如何估计」，按代码回答会与论文正文冲突；按论文回答则与代码冲突。
2. **方法论风险**：`limit_direction="both"` 与「T-2 特征对齐」的初衷直接矛盾——特征本身被允许吸收未来信息。
3. **量级判断**：面板 22,814 行、测试年 3,372 行占比 14.8%，对分位点与中位数的估计影响通常在千分位到百分位量级（AUC 波动通常 <0.005），因此**预期不会推翻当前结论**，但必须实测确认而非推断。

**《中期可行性分析与建议方案设计》§0.3 第 4 条** 已于 2026-11-13 明确提出该问题，其余 4 条（二值 IV、扩展窗口 CV、2022/2023 切分、官方标签）均已落地，**仅此条未落地**。

**建议动作**：见《ADR-007 预处理无泄漏化》——给出 3 个候选方案（A：全流程前向化 + 训练期统计量；B：仅修复缩尾、保留双向插补；C：保持现状但在论文中降级表述），建议选 A，需重跑训练并同步全部指标。

## 4. 本轮边界声明

本轮是**纯文档工程**，刻意划出以下边界，理由是：方法学修复涉及重训与指标重算，一旦数字变动会波及论文、README、首页数据块与报告模板，需独立一轮并留出复核时间。

| 不做的事 | 原因 | 建议处置 |
|---|---|---|
| 不改 `etl/clean_financial.py` 的三处泄漏 | 改动必然导致全部指标变动，需同步 5+ 处数字来源 | P1 阶段按 ADR-007 一次做完并冻结 |
| 不重训、不改 `models/artifacts/` | 同上；且 2024 锁箱需 2026 官方标签才能真正验证 | P1 阶段 |
| 不改论文实测数字 | 现有数字与 `README.md`、`论文_第1-4章.md`、`index.html` 三方一致，本轮只补来源与口径说明 | — |
| 不改 `.py` / `.vue` / `config/settings.py` | 用户明确限定「仅文档」；`DESIGN_DIR` 悬空常量不影响运行 | P-11 一行修复 |
| 不改 CI | CI 变更需与前端构建环境、ruff 版本共同验证 | P2 阶段，先在本文档中给出建议 |
| 不删除任何 PDF / docx 原始附件 | 原始交付物只读 | — |
| 不重命名 `api/`、`models/` 等代码目录 | 与文档治理正交，收益低风险高 | — |
