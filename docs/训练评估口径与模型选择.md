# 训练、评估口径与模型选择

> 目的：把"指标怎么算、模型怎么选、哪些数不能拿来比"写死，避免答辩时被问"为什么验证 PR-AUC 更高的模型没被选中"。
> 适用版本：2026-11-14 之后的 `models/train.py`（含对比表、运行快照、可选调优目标）。

---

## 1. 一句话结论

- **主模型是"设定"而非"竞标"**：项目固定 XGBoost 为主模型（`selection.rule=designated_primary_model`），其余四个模型是对照组。
- **测试集只应用、不选择**：阈值、校准器、超参全部在训练/验证集上定，测试集（2023）只评估一次。
- **验证集只有 75 个正样本**，PR-AUC / Recall@Top10 的方差很大；30 → 50 次 Optuna 试验让验证 PR-AUC 从 0.3981 升到 0.4116，但测试 PR-AUC 反而从 0.4268 降到 0.3986。这是"在验证集上多试几次"的过拟合证据，**不应继续加 trials**。

---

## 2. 模型选择规则

| 项 | 规则 | 代码/产物 |
|---|---|---|
| 主模型 | 固定 XGBoost（调优后） | `models/train.py::train_all` |
| 对照模型 | LogisticRegression / RandomForest / XGBoost(未调优) / LightGBM / CatBoost | `metrics.json` |
| 超参搜索 | Optuna TPE，`--trials` 控制预算，默认 30 | `run_manifest.json::params.tuning_best_params` |
| 调优目标 | `--objective auc`（默认）/ `pr_auc`（头部排序导向） | `run_manifest.json::params.objective` |
| 概率校准 | isotonic，验证集 5 折**交叉拟合**评估；部署校准器用全验证集拟合 | `metrics.json::calibration.scope=cross_fitted_valid_5fold` |
| 预警阈值 | 在校准后验证集上按 FN:FP=10:1 成本最小化冻结 | `model_meta.json::threshold` |
| Top-K | `TOP_K_PRIMARY=0.10` 指**前 10% 样本**（2023 测试集 = 338 家），不是"前 10 家" | `model_meta.json::top_k` |
| 测试集 | 只应用冻结的阈值与校准器，报告一次 | `metrics.json::test_2023` |

> 每次训练都会写 `models/artifacts/model_comparison.csv`（五模型 + 调优版的验证/测试指标），
> 并把模型、校准器、指标、元信息复制到 `models/artifacts/runs/<run_id>/`，历史版本不再被覆盖。

## 3. 指标口径

| 指标 | 口径 | 注意 |
|---|---|---|
| AUC | 排序能力，阈值无关 | 类不平衡下容易"看起来很好" |
| PR-AUC | 正类精确率-召回率曲线下面积 | 基础率 3%–4% 时比 AUC 更敏感，但方差大 |
| KS | max(TPR−FPR) | 与 AUC 高度相关，别当独立证据 |
| Recall@Top10% | 按分数取前 10% 样本，命中正样本 / 全部正样本 | 与人工复核容量直接对应 |
| ECE | 校准后可靠性的期望偏差 | 验证集 ECE 用交叉拟合概率，非样本内 |
| Brier | 概率预测的均方误差 | 同时反映区分度与校准 |
| 成本 | `10×FN + 1×FP`（可配） | 阈值选择的依据 |

**测试集指标并没有"缺失"**：`metrics.json` 的每个模型下都有 `test_2023` 节点（AUC/PR/KS/ECE/Brier/混淆矩阵/Top-K）。
此前只是没有打印到控制台，现已加入训练末尾的对比表（同时落盘 `model_comparison.csv`）。

## 4. 当前指标（`run_id=20261114-213525-da08d92c`，50 trials）

| 模型 | 验证 AUC | 验证 PR | 验证 R@10% | 测试 AUC | 测试 PR | 测试 R@10% | 测试 ECE |
|---|---:|---:|---:|---:|---:|---:|---:|
| LogisticRegression | 0.8977 | **0.4304** | 0.7467 | 0.8863 | **0.4367** | 0.6772 | 0.0145 |
| RandomForest | 0.9002 | 0.3577 | 0.7200 | 0.8917 | 0.3832 | 0.6772 | 0.0125 |
| XGBoost（未调优） | 0.8901 | 0.3694 | 0.6933 | 0.8852 | 0.3800 | 0.6535 | 0.0129 |
| LightGBM | 0.9062 | 0.3769 | 0.7067 | 0.8874 | 0.3792 | 0.6378 | 0.0132 |
| CatBoost | **0.9127** | 0.3801 | 0.7200 | **0.8969** | 0.3798 | 0.6378 | 0.0136 |
| **XGBoost(tuned，主模型)** | 0.9196 | 0.4116 | 0.7467 | 0.8962 | 0.3986 | 0.6693 | 0.0126 |

> 主模型不是"验证指标最高的模型"：验证 AUC 最高是 CatBoost，验证/测试 PR-AUC 最高是 LogisticRegression。
> 选择 XGBoost 的理由是**论文设定 + SHAP 可解释性 + 非线性交互**，不是指标竞标；这一点必须在论文与答辩中明说。

### 4.1 30 trials 与 50 trials 的对比（重要）

| 运行 | 验证 PR-AUC | 测试 PR-AUC | 说明 |
|---|---:|---:|---|
| 30 trials (`20261114-211237-da08d92c`) | 0.3981 | **0.4268** | 验证更差、测试更好 |
| 50 trials (`20261114-212459-da08d92c`) | **0.4116** | 0.3986 | 验证更好、测试更差 |

结论：**在 75 个正样本的验证集上反复调优，提升的是验证集排序，不是泛化能力**。建议固定 `--trials 30` 并冻结一次结果；若要比较 trials，应在交叉验证的均值/标准差上比较，而不是单点验证 PR-AUC。

## 5. 已知局限与应对

| 局限 | 证据 | 应对 |
|---|---|---|
| 验证集正样本仅 75 个 | 3,209 × 2.34% | 报告阈值附近混淆矩阵与 Top-K，不只报单点 PR-AUC；用 CV 均值±标准差做稳健性 |
| 验证集正样本率显著低于训练/测试 | 4.39% / 2.34% / 3.77% | 论文披露 2022 年 ST 实施数偏少；不做重采样，避免改变先验 |
| 校准器在验证集拟合 | 部署校准器用全验证集；评估用交叉拟合 | 已区分"评估口径"与"部署口径"；测试 ECE 不受测试集泄露影响 |
| 单种子结果 | XGBoost `n_jobs=-1` + 固定 seed | 如需报误差，跑 3–5 个 seed 取均值±标准差（尚未默认执行） |
| 主模型固定 | 见 §2 | 在论文"模型选择"小节写明理由，并附对比表 |
| 30/50 trials 结果差异 | 见 §4.1 | 固定预算并冻结；不要在测试集上"挑更好的那次" |

## 6. 复现

```bash
# 默认预算，主模型固定 XGBoost，目标 AUC
python -m models.train --trials 30

# 若确需以头部排序为目标（需在论文中说明并固定）
python -m models.train --trials 30 --objective pr_auc

# 只看当前产物的对比表
python -c "import pandas as pd; print(pd.read_csv('models/artifacts/model_comparison.csv'))"
```

产物：

| 文件 | 内容 |
|---|---|
| `models/artifacts/model_comparison.csv` | 五模型 + 调优版的验证/测试指标 |
| `models/artifacts/run_manifest.json` | 数据/特征/参数/阈值/环境 + `selection` 选择规则 |
| `models/artifacts/runs/<run_id>/` | 该次运行的模型、校准器、指标、元信息快照 |
| `models/artifacts/run_history.jsonl` | 历次运行索引（追加） |
