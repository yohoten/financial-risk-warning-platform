## 3. 诉讼仲裁

### 3.1 来源

- 路径：公司研究系列 → **诉讼仲裁** → 诉讼仲裁明细表；
- 物理表：`LA_DETAIL`；
- 导出：全部 A 股，1996-04-24 至 2026-11-11，CSV，全部 29 个字段；
- 原始 **155,603 行 × 29 列**；`EventID` 唯一事件 **77,470 个**（同一事件多次公告会重复）；
- 有效公告日期 155,369 行；`LAValue`、`Currency`、`LATypes`、`LAStatus` 等可用。

### 3.2 清洗口径

1. 仅保留 `DeclareDate` 为 `YYYY-MM-DD` 的行；
2. 去掉空 `EventID`；
3. 同一 `EventID` 保留**最后一次公告**，避免同一诉讼被多次计数；
4. 过滤 2013–2026 年；
5. 公司-年聚合：`litigation_count = nunique(EventID)`；`lawsuit_amount_cny` 只汇总 `Currency=CNY` 的 `LAValue`；非人民币事件数单独记 `non_cny_count`。

结果：

- **71,746 个诉讼/仲裁事件**，2,917 家公司；
- **9,589 个公司-年**有诉讼记录；
- 与财务主表匹配 7,861 个公司-年（15.06%）；
- 事件字段保留：代码、简称、事件 ID、公告类型/日期、事件发生日期、司法类型、原告/被告、案由、涉案金额、币种、审理机构、司法进程、执行状态、损益影响。

### 3.3 使用注意

- `LAValue` 是涉案金额，不等于最终损失；币种混合，不能直接把 USD/HKD 等与 CNY 相加；
- `DeclareDate` 是公告日，`EventSignDate` 是事件发生日；建模时必须按公告日做时点对齐，避免前视；
- 同一事件多次公告已去重；若研究“诉讼进展”而不是“诉讼发生”，应保留公告序列，不能用本事件表替代。
